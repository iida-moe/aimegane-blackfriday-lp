まとめ

お客さまが進む順（広告 → LP → 予約フォーム → お店）に、わかったことをまとめました。

広告：人は安く集まったが、広告によって「来る人の質」がまったくちがう
  • Yahoo!ディスプレイは、来た人の約9割がLPの一番上だけ見て帰っていた（平均6秒）。11/18に止めたのは正解
  • Yahoo!ディスプレイを止めたあと、LPに来る人は1日約1,300人 → 約530人に減ったが、クーポン伝票は1日約13件 → 約15件に増えた
  • 検索広告（Google・Yahoo!）からLPに来た人は約420人で、P-MAX（約3,300人）やメタ（約2,900人）よりずっと少ない。でも、来た人は一番よく読んで、一番ボタンを押している（しっかり見た人 約7割・ボタンを押した人 約2割）
  • P-MAXは、LPに1人来てもらうのにかかった広告費が約30円で、検索広告（約320円）の約10分の1。しかも来た人の半分以上がしっかり見ている
  • メタは1人あたり約50円でP-MAXより高く、しっかり見た人は約3割。P-MAXより「高くて、読まれていない」
LP：見た人は「予約」より「地図」を押している。すぐ直せる「もったいない」もある
  • 「地図・営業時間を見る」を押した人 226人／「Web予約」を押した人 62人
  • 一番上の画像（FV）が1,333回タップされているのに、押しても何も起きない
  • スマホで来た人の半分は、一番上だけ見て帰っている
予約フォーム：開いた79人のうち、予約できたのは4人
  • 一番やめているのは「お名前などの入力」。入力を始めた17人のうち、確認画面まで進んだのは5人
  • 日時を選ぶところでも約半分がやめている。Web予約は多くの店で「3日後から」しか取れない
お店：予約しないで来店してクーポンを使った人が多い
  • BFクーポン伝票は—。予約の4件よりずっと多い
  • だから、予約の数だけで広告の良し悪しを決めると、まちがえる
  • ただし、クーポンを使った人が「広告を見て来た人」か「もともと来る予定だった人」かは、まだわからない（新規か既存かを調べて追加します）

            LPの中の行動

            GA4（ボタンが押された数）とClarity（スクロール・タップの記録）。

            押されたボタン

            押した人の数（11/13〜11/26）。LPを見た人は約11,900人。

            • 一番押されたのは、一番上（FV）の「近くのお店で予約する」。次が「店舗検索」と「現在地から探す」
            • LPの途中にあるボタン（商品の下・選ばれる理由の下・最後）は、下にいくほど押されなくなる
            • 「クーポンを見る」はメタから来た人がほとんど

            押しても何も起きなかったところ

            Clarityの「デッドクリック」（押しても反応がない）と「イライラクリック」（同じところを何度も押す）。

            • 一番上の画像は、セール名・期間・「遠近両用も追加0円」などが大きく入っていて、広告のバナーのように見える。押せばくわしい内容が出ると思われている可能性がある
            • 「近くのお店で予約する」は、押すと同じページの下に移動するので、反応がないと数えられている可能性がある（実際は動いている）
            • 「現在地から探す」は、位置情報の許可を求める画面が出るまでの間に、反応がないと数えられている可能性がある

            LPのあと、どこへ行ったか

            LPから先に進んだ人の数（GA4・11/13〜11/26・押した人の数）。

            • 同じ人が地図とWeb予約の両方を押すこともあるので、合計はぴったりではない
            • 「アイメガネのトップページ」は、LPのロゴを押して移動した人と考えられる
            • 地図を押したあと、実際にお店に行ったかどうかはGA4ではわからない

            LPの次の手（ウィンターセールにむけて）

            • 一番上の画像（FV）を押したら、お店さがしに移動するようにする
            • 商品の画像を押したら、大きく見られるようにする
            • 一番上で帰る人が半分いるので、一番上に「期間」「何がおトクか」「近くのお店」をまとめる
            • 「地図を見てそのままお店に行く人」が多いので、地図ボタンは残す。そのうえで、地図の横に「予約すると待たずに案内できます」など、予約するよさを書く

              来店・購入お店

              BFクーポンの利用

              データライザーのBFクーポン伝票（注文日・11/13〜11/26）。

              クーポンの種類ごと

              クーポンが使われた回数。1枚の伝票で2種類使った例が8件あるので、合計は伝票の数より多くなります。

              お店ごと（伝票が多い順・上位10店）

              • 33店で使われている
              • 1伝票の金額は、真ん中の値で19,000円。1〜2万円の伝票が一番多い（83件）
              • おもちゃのまち西口店の11/20の伝票（489,600円）は、11/26に取り消しになっている。売上の合計にはこの分が入ったまま
              このあと追加します。
              • クーポンを使った人は、はじめてのお客さまかリピーターか（クーポンの種類ごと）
              • 全店の売上：BFの前の14日間（10/30〜11/12）とのくらべ
              • 予約した4人が来店・購入したか

              効果の測り方の次の手（ウィンターセールにむけて）

              • 「予約の数」だけでなく「クーポン伝票の数」も目標にする
              • 広告ごとにクーポンを分けて、どの広告から来たお客さまか、お店でわかるようにする
              • クーポンを使った人が新規か既存かを、セール中から毎週見る

              ウィンターセールでの案：予約フォームにセール期間を書く

              予約フォームの最初の画面（メニューを選ぶところ）に、文字だけで入れる案です。

              文の例

              ただいまWINTER SALE開催中（12/27（日）まで）
              ※Web予約は3日後から承っています。お急ぎの方はお電話でご予約ください。

              入れる理由

              • BFでは、予約フォームを開いた79人のうち、メニューを選んだのは53人。最初の画面で3人に1人がやめている
              • いまのフォームには、セール中であることも期間も書かれていない。LPから来た人が「これでセールの予約になっているのか」迷っている可能性がある
              • 日時を選ぶところでも約4割がやめている（53人 → 33人）。「3日後から」しか選べないことと、電話でも予約できることを先に伝える

              決めておくこと

              • 予約フォームはセール以外のお客さまも使う共通の画面。セールが終わったら消す人と日にちを決める（日付が過ぎたら自動で消える形にできれば、消し忘れがない）
              • HPの担当の方に相談する。セールは12/4からなので、来週の前半までにお願いしたい
